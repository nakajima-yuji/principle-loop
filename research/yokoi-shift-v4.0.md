## 中心原理（維持）
**前提を維持し、用途や関係を転換する。**
PRINCIPLE LOOPの独立選択式モジュール。常時実行せず、固定順序・他モジュールとの強制接続を設けない。成功パターンの量産テンプレートにはしない。

## 既存の操作（維持）
v2.0の7操作: FIX / REMOVE / TRANSFER / RELATION / CONSTRAINT / NEW FIELD / DISCOVERY。
v3.0の5候補: COGNITIVE COMPLETION / DOMAIN RELOCATION / FUNCTION WITHOUT OBJECT / EXPERIENCE-CRITICAL PROPERTY / IDEA PROTECTION。
各操作の定義と根拠は前版を参照。

## v4.0で追加する3つの独立候補

### 1. BENEFIT MIGRATION（利点の移動）
**問い**: 最初の問題を解決した仕組みが、別の環境では異なる理由で価値を持たないか？
事例: 十字キーはゲーム＆ウオッチの薄型化に適した入力として開発され、ファミコンではコスト面の利点も採用理由となったと横井が説明。
独自抽出: 同じ部品でも「採用する理由」が移植先で変わる。単純なTRANSFERと区別する。
検証: 別の利点は実際に測定・確認できるか？

### 2. PARTIAL ADOPTION（部分採用）
**問い**: 技術・製品の全体が不適切でも、特定の性質だけは利用できないか？
事例: バーチャルボーイ開発で当時のVR技術全体を採用せず、視界を覆う立体表示の要素に着目したという本人の説明。
独自抽出: 技術の採否を二択にせず、構成要素単位で判断する。
検証: 取り出した要素だけで目的の体験が成立するか？

### 3. CROSS-DOMAIN PROOF（異分野実証）
**問い**: 他分野の現物や現象で、既存の前提を疑う根拠を示せないか？
事例: ゲーム＆ウオッチの小型画面への懸念に対し、雑誌の小さな写真を例に視認可能性を示したという本人の説明。
独自抽出: 異分野を発想源だけでなく、仮説を試す根拠として使う。
限界: 小さな写真を認識できることは、小さなゲーム画面の操作性まで証明しない。類推の境界を検証する。

**注意**: 3つとも横井本人の命名ではなく、資料を手掛かりにPRINCIPLE LOOPが独自に抽出した候補。既存操作との独立性は未検証。

## DECISION CHECK（独立した任意の判断検証レイヤー）
1. **成立性** — 必要な機能は残っているか？
2. **代償** — 削除・転換によって何を失ったか？
3. **比較軸** — 既存製品の性能軸で比較するのは適切か？
4. **伝達性** — 実際に触れる前に新しい体験の価値は伝わるか？
5. **再利用性** — 当初の目的以外に利点がないか？

未知の案を早期棄却しない。検証は必要な場面だけ任意に行う。

## 反証と調査上の注意
- バーチャルボーイの商業的不成功を単一の原因で説明しない。価格、ソフト、体験の伝達、装着・利用環境、期待との不一致を分離して調べる。
- ゲーム＆ウオッチの「新幹線で電卓を使う人」逸話は広く流通するが、関係者が詳細を知らないと述べる資料もある。本人の直接発言と後年の回想を混同しない。
- 横井本人の発言／資料からの推論／PRINCIPLE LOOP独自拡張を区別する。
- 横井個人の判断とチーム全体の意思決定を混同しない。
