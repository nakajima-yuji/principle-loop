## 中心原理（維持）
**前提を維持し、用途や関係を転換する。**
PRINCIPLE LOOPの独立選択式モジュール。常時実行・固定順序・他モジュールとの強制接続はしない。

## v6.0の目的
新しい操作を増やすことではなく、既存18操作・候補（v2.0の7、v3.0の5、v4.0の3、v5.0の3）について、独立性、重複、矛盾、失敗条件を反証する。別途v5.0のIDEA–ENVIRONMENT FITも研究軸として扱う。

**最初の発見**: 「変換操作」「判断・評価方法」「成立条件・保護方法」が混在していた。操作名よりも、変換が生んだ実際の差分を重視する。

## 重複・矛盾の監査（8組）
| 比較 | 重複・矛盾の疑い | 暫定判断 |
| --- | --- | --- |
| REMOVE × COGNITIVE COMPLETION | どちらも情報削減に関係 | REMOVEは削除、後者は認知が欠落を補う条件。区別 |
| TRANSFER × BENEFIT MIGRATION | 別用途への移植 | 移植先で価値・採用理由が変わる点を後者の特徴として親子関係を検討 |
| REMOVE × FUNCTION WITHOUT OBJECT | 実体の除去 | 後者は機能を残す特定のREMOVEとして親子関係を検討 |
| RELATION × CHANGE LEVERAGE | 関係変更とその効果 | 操作と評価基準に分離 |
| CONSTRAINT × COST OF ADDITION | 制約・負担 | 操作と評価基準に分離 |
| IDEA PROTECTION × IDEA–ENVIRONMENT FIT | 既存評価から企画を守る | 保護行為と評価・実現環境の適合を区別 |
| NEW FIELD × EXPERIENCE ACCESS | 新市場とユーザーの入口 | 新しい遊びの創出と到達性は別問題 |
| EXPERIENCE-CRITICAL PROPERTY × FIX | 体験の核を守る | 固定対象の定義と技術選定基準を区別 |

## 本人発言・開発事例を使った反例

### A. 横井は何でも削るわけではない
ゲーム＆ウオッチの2画面化では、単なる画面数の増加でなく2画面を意味ある遊びとして接続することを重視したという本人の説明。
**反証**: REMOVEを常に優先することはできない。機能追加による関係性の生成が有効な場合もある。

### B. 見た目・性能を削れば常に成立するわけではない
キャラクターを点に置き換えて動きの面白さを考える一方、見た目が敵の役割を理解させる機能も持つ。
**反証**: 情報削減は「情報量」だけでなく、残すべき機能を特定する必要がある。

### C. 新しい体験を作っても従来の期待から自由にはならない
バーチャルボーイについて、一般層向けの新体験という狙いと、従来ゲーム機としての期待とのずれが本人の対談からうかがえる。
**反証**: NEW FIELD（新しい遊びの領域）とEXPERIENCE ACCESS（利用者が体験へ到達する条件）は独立した課題。

### D. 発案者自身が予測しなかった成功
ゲーム＆ウオッチ『オイルパニック』は2画面である必然性を意図した設計だったが、『ドンキーコング』は2画面への分割によって視線移動など想定外の面白さが生まれたと横井が回想。
**反証**: 設計者が変更の効き目を事前に正確に見抜けるとは限らない。
**CHANGE LEVERAGEの修正**: 「変更の効き目を仮説として予測し、実際の反応との差から更新する評価方法」とする。DISCOVERYとは関連するが同一ではない。

## v6.0暫定分類（必須の工程順ではない）
### A. 変換操作に近い候補
FIX / REMOVE / TRANSFER / RELATION / CONSTRAINT / NEW FIELD / DISCOVERY / DOMAIN RELOCATION / FUNCTION WITHOUT OBJECT / BENEFIT MIGRATION / PARTIAL ADOPTION / CROSS-DOMAIN PROOF

### B. 判断・評価方法に近い候補
EXPERIENCE-CRITICAL PROPERTY / CHANGE LEVERAGE / COST OF ADDITION / EXPERIENCE ACCESS

### C. 成立条件・保護方法に近い候補
COGNITIVE COMPLETION / IDEA PROTECTION / IDEA–ENVIRONMENT FIT

**分類上の留保**: FIX、DISCOVERY、CROSS-DOMAIN PROOFはA内でも「変換」そのものではなく前提設定・発見・検証に近い。次回の監査対象とする。A/B/Cの合計19項目は18候補と追加の研究軸を含むものであり「正式19操作」を意味しない。

## PRINCIPLE LOOPへの提案: 操作名より実験差分を記録
1. **元の前提** — 何を維持したか
2. **変更点** — 何を変えたか
3. **予測** — 何が面白くなると考えたか
4. **実際の反応** — 何が起きたか
5. **予測との差** — 想定外の価値・問題
6. **次の判断** — 維持／再試作／保留

## 研究結果
- 新規操作: **0件**
- 重点反証: **8組**
- 本人発言・事例に基づく反例: **3論点**、加えて予測外の成功事例
- 正式廃止: **0件**（独立性検証まで保留）

**結論**: 横井シフトは「優れた発想を一度で当てる」仕組みではなく、前提を変え、試し、予測しなかった価値を発見する仕組みとして強化する。
