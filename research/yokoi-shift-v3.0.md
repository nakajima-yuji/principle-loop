## 不変の中心原理
**前提を維持し、用途や関係を転換する。**
v2.0の7操作（FIX / REMOVE / TRANSFER / RELATION / CONSTRAINT / NEW FIELD / DISCOVERY）は全て維持。順序・必須実行・他モジュールとの固定接続を設けない。

## 新しい5つの操作候補（既存7操作へ無理に統合しない）
1. **COGNITIVE COMPLETION / 認知補完**: 表現を削った際、利用者の想像・知覚が補える範囲を探る。
2. **DOMAIN RELOCATION / 成立場所の移転**: 現実に確保できない機能を画面内など別領域に移す。
3. **FUNCTION WITHOUT OBJECT / 実体なき機能**: 物理的実体を消しても、働きだけを残す。
4. **EXPERIENCE-CRITICAL PROPERTY / 体験決定特性**: 技術の一般的な性能ではなく、目的の体験を成立させる性質を選ぶ。
5. **IDEA PROTECTION / 未知企画の保護**: 既存評価軸による早期棄却を防ぎ、最小試作の機会を確保する。

これらは本人が命名した操作ではなく、資料を基にしたPRINCIPLE LOOP独自の抽出・拡張。独立性と再現性は未検証。

## 失敗・矛盾: バーチャルボーイ
本人は既存ゲームとは異なる立体体験を狙ったが、従来のゲーム機として比較された問題を語った。
**仮説（原因確定ではない）**
- 体験と期待の不一致
- 写真・動画等では伝えにくい体験価値
- 試遊までの入口の設計
- 価格・姿勢・ソフト・販売など他要因の切り分けが必要

**検証問い**: 新しい遊びを古い評価軸で誤解されていないか？ 実際に触れるまで価値が伝わらないか？ 入口を設計できているか？

## 統合原理候補
**物理的・技術的な要素を減らす → 別の仕組みが機能を補う → 体験が維持・拡張される。**
削れば必ず面白くなるわけではない。「何が不足を補うか」を具体的に説明・検証する。

## 次の研究課題（v3.1 / v4.0候補）
- 横井個人と開発チームの判断の切り分け
- 新5操作が既存7操作から独立しているかの反証
- バーチャルボーイの開発・販売・利用者側の一次証言
- 削除ではなく追加が有効だった製品事例
- 成功例・失敗例双方から、判断の境界条件を探る
