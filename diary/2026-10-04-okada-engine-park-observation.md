# 2026-10-04 — 公園観察から岡田エンジンへ

## 今日の位置づけ

PRINCIPLE LOOPは「アイデアを自動生成する仕組み」ではなく、観察した現象から再利用可能な構造を取り出し、その構造を深掘り・展開・実験し、原理として育てていく仕組み。

今日、現象から構造を抜き出す工程を明確化し、この処理を **岡田エンジン** と呼ぶことにした。

現在の大枠：

**観察 → 岡田エンジン → 構造の種 → 展開 → 選別 → 最小実験 → 観測 → 原理更新**

重要：岡田エンジンとゲーム企画を混ぜない。岡田エンジンは「面白い案を作る」のではなく、「現象を別の場所にも持っていける構造にする」ためのもの。

---

## 出発点：公園での観察

公園で、アリ・蜘蛛・蜘蛛の巣・消防車・小屋遊びなどを観察した。

特に今回深掘りしたのは「蜘蛛の巣を見つけ、蜘蛛を探した」という現象。

表面だけなら「蜘蛛探し」だが、ここから固有要素を除去していく。

---

## 岡田エンジン

毎回、AIが次の4問を行う。

1. **固有名詞を全部消すと何が残る？**
2. **何と何の関係によって、この現象は成立している？**
3. **まったく違う分野に、同じ構造は存在する？**
4. **その構造だけを別の対象へ移したら何ができる？**

今回：

「蜘蛛の巣を探した」
→ 蜘蛛・巣・公園を消す
→ **本体は見えないが、痕跡は見える**

異分野で同型構造を探すと、

- 足跡 → 動物
- 煙 → 火
- 波紋 → 魚
- 物音 → 人・生物
- 食痕 → 生物
- 影 → 本体
- 気配 → 見えない存在

などがある。

ここから得られた構造の種：

> **見えないものを、痕跡から探す。**

ここまでで岡田エンジンはいったん終了する。

「本体より先に痕跡を見せると探索が始まる」は原理として確定しない。構造と仮説を分け、実験前に結論を固定しない。

---

## 岡田エンジン後の「展開」

構造の種をすぐ具体的なゲーム案に固定しない。

まず構造そのものを変形して可能性を広げる。

例：

- 名詞を変える
- 痕跡の性質を変える
- 動詞を変える
- 順番を変える
- 因果を反転する
- 役割を増やす
- 二者関係にする
- 複数の構造を組み合わせる

### 今日うまくいった展開

**見えないものを、痕跡から探す**
→ 一人で探す構造を二者関係にする
→ 自分も相手も見えない
→ 双方が行動すると痕跡を残す
→ 相手の痕跡を探し、自分の痕跡は隠したい
→ **透明人間対決**

ここで「探索」だけだった構造に、

**探す ↔ 隠す**

という相互関係と戦略性が生まれた。

重要なのは「透明人間」という題材そのものではなく、

> **見えない相手を痕跡から探す × 自分も痕跡を残してしまう**

という構造。

---

## 新たに気になった方向：痕跡を自分から発生させる

今日さらに面白いと感じたのが次の流れ。

プレイヤーが地面に餌を置く。

→ 何も起こらない  
→ 離れて戻る  
→ 餌がなくなっている  
→ もっと餌を置く  
→ 今度は足跡が残っている  
→ 気配が濃くなる  
→ 見えない何かの行動・位置・性質を推測する

これは単なる「痕跡を追う」から一段変化している。

元：
**本体 → 痕跡 → プレイヤーが発見**

変形：
**プレイヤーの行為 → 見えない本体が反応 → 痕跡が発生 → 推測 → 次の行為**

つまりプレイヤーが環境へ働きかけることで、見えない対象から情報を引き出す。

ここには戦略ゲームへ発展する可能性がある。

- どこに餌を置くか
- 何を置くか
- いつ戻るか
- どの痕跡を信用するか
- 相手の行動を予測する
- わざと反応を起こす
- 相手に自分の位置を悟られない

まだゲーム仕様には固定しない。**「気配」「足跡」「餌→反応」周辺は、構造の種として保存してさらに展開する。**

---

## 現在の各要素の役割

### PRINCIPLE LOOP
全体システム。観察から原理を育て、別用途へ応用し、実験で更新していく。

### 岡田エンジン
PRINCIPLE LOOP内部の「構造抽出エンジン」。

**表面分解 → 固有要素除去 → 関係抽出 → 異分野同型探索 → 構造移植**

目的はアイデア完成ではなく、汎用的な「構造の種」を作ること。

### 展開工程
岡田エンジンで得た構造の種を壊さず、変形して可能性を広げる。

### 実験
面白そうな案を最小サイズで実装し、本当に人の行動が起きるかを見る。Three.js等はここで使う実装手段であり、原理そのものではない。

### 原理
最初から決めない。構造を移植し、実験・観測した結果から少しずつ強くする。

---

## 今日の重要な学び

**早く具体化すると、せっかく抜き出した構造が一つのゲーム案に閉じてしまう。**

したがって、

> **構造を抜く → 構造のまま複数方向へ展開する → 面白いものだけ具体化する**

の順番を守る。

今回の公園観察から、

**蜘蛛の巣 → 痕跡 → 見えないものを痕跡から探す → 二者関係化 → 透明人間対決**

という飛躍が実際に起きた。

これはPRINCIPLE LOOPにおける「観察から創作へ飛躍する経路」の重要な実例として残す。

次の探索対象：

> **気配・足跡・餌・反応・見えない存在を使って、どのように戦略性が自然発生するか。**


---

## 岡田エンジンは再帰できる（2周目）

透明人間対決／透明FPSまで具体化したところで、完成案として止めず、もう一度岡田エンジンへ戻した。

入力：

> 透明なプレイヤー同士が、足音・足跡・気配などから相手の位置を推測して戦う。行動すると自分の痕跡も残る。

### ① 固有名詞を全部消す

FPS・透明人間・銃・プレイヤー・足跡などを消す。

残る構造候補：

> **互いの存在を直接確認できない。しかし行動すると情報が外部に漏れる。**

さらに圧縮：

> **行動すると、存在が漏れる。**

### ② 関係を抜く

中心にある関係は、

**行動 ↔ 情報漏洩**

何もしない
→ 見つかりにくい
→ しかし相手の情報も得にくい

動く
→ 情報を得られる
→ しかし自分の情報も相手に与える

構造の種：

> **情報を取りに行くほど、自分の情報も漏れる。**

### ③ 異分野の同型構造

- 潜水艦：探知のために能動的に働きかけることが、自分の存在を察知されるリスクにもなる
- かくれんぼ：相手を見るために顔を出すと、自分も見つかりやすくなる
- 捕食・被食：獲物を探して動くほど、自分も捕食者から発見されやすくなる
- ポーカー等：相手の情報を取ろうとする行動そのものから、自分の意図も読まれる

透明FPS固有ではなく、異分野にも移植可能な関係と考えられる。

### ④ 構造だけを別対象へ移せる状態にする

一周目：

> **見えないものを、痕跡から探す。**

二周目：

> **情報を取りに行くほど、自分の情報も漏れる。**

ここで岡田エンジンを止め、次の展開候補として保存する。

---

## PRINCIPLE LOOPへの追加：再帰ループ

今日の発見は、岡田エンジンが一回限りの処理ではないこと。

**観察 → 岡田エンジン → 構造A → 展開 → 具体案 → 岡田エンジン → 構造B → 展開 → …**

と再帰できる。

今回：

**蜘蛛の巣を探す**
→ 岡田エンジン①
→ **見えないものを、痕跡から探す**
→ 展開
→ **透明人間対決／透明FPS**
→ 岡田エンジン②
→ **情報を取りに行くほど、自分の情報も漏れる**

重要なのは、具体化を終点にしないこと。

> **具体案が生まれたら、それ自体を新しい現象として再び分解できる。**

これにより、アイデアを作るたびに「完成案」だけでなく、別用途へ移植できる構造のストックも増えていく。

PRINCIPLE LOOPは一方向のパイプラインではなく、

> **具体 → 抽象 → 異分野 → 再具体化 → 再抽象化**

を何周もできる循環系として扱う。

### 現時点の位置づけ

**PRINCIPLE LOOP**
= 観察・構造抽出・展開・実験・観測・原理更新を循環させる全体システム。

**岡田エンジン**
= その内部で、現象や具体案から移植可能な構造を取り出すエンジン。必要なら何周でも再投入できる。

**展開工程**
= 抽出した構造を二者関係化、反転、役割追加、組み合わせ等で変形し、別の具体案へ移す工程。

**実験**
= 具体案を最小実装して、人の行動・面白さ・予想外の現象を観測する工程。

**原理更新**
= 実験で得た現象を再び岡田エンジンへ投入し、構造や仮説を更新する工程。

この再帰性を、今後のPRINCIPLE LOOPの基本動作として残す。

# 2026-10-05 追記 — PRINCIPLE LOOPシステム整理 / TRACE

## PRINCIPLE LOOPの現在の整理

PRINCIPLE LOOPは、単に「原理を見つける仕組み」ではない。

> **原理・構造を固定せず、抽出・移植・変形・実験・再観察を繰り返しながら育てる循環システム。**

基本ループは次の4工程で整理する。

1. **OBSERVE｜観察する**  
   日常・遊び・仕事・自然・技術などから、なぜか気になる現象を拾う。
2. **EXTRACT｜構造を抜き出す（岡田エンジン）**  
   固有要素を外し、関係を抽出し、異分野の同型構造を探し、別対象へ移植可能な「構造の種」にする。
3. **TRANSFORM｜変形・移植する（展開工程）**  
   二者化、反転、役割追加、強弱化、順序変更、モチーフ交換、既存システムとの組み合わせ等で構造を育てる。
4. **TEST｜具体化・実験する**  
   JS / Three.js等で最小実装し、実際に人がどう行動するかを観測する。

そしてTESTで得られた新しい現象を再びOBSERVEへ戻す。

> **OBSERVE → EXTRACT → TRANSFORM → TEST → OBSERVE → …**

### 岡田エンジンの位置づけ

岡田エンジンは単なる「置き換えエンジン」ではなく、より正確には、

> **具体から構造を抜き出し、別の具体へ移植可能にする構造抽出・構造移植エンジン。**

固定4問：

1. 固有名詞を全部消すと何が残る？
2. 何と何の関係によって、この現象は成立している？
3. まったく違う分野に、同じ構造は存在する？
4. その構造だけを別の対象へ移したら何ができる？

岡田エンジンは「完成案を作る」ところまで担当しない。構造の種が得られたら展開工程へ渡す。

### 展開工程の位置づけ

展開工程は、構造の種を固定せずに変形する場所。

今回特に重要だった操作：

- 一人の探索を二者関係へ変える
- 観測と被観測を相互化する
- 情報量とリスクを連動させる
- 真の痕跡に偽装・罠を混ぜる
- 既存ゲームシステム（FPS、罠、偽装等）を部品として組み合わせる
- 構造を残したままモチーフを交換する

### PRINCIPLE LOOPの再帰性

具体化は終点ではない。

> **具体案 → 岡田エンジン → 新しい構造 → 展開 → 次の具体案**

と何度でも戻せる。

今回の系譜：

**蜘蛛の巣を探す**  
→ **見えないものを痕跡から探す**  
→ 透明人間対決 / 透明FPS  
→ **情報を取りに行くほど、自分の情報も漏れる**  
→ **観測 ↔ 被観測**  
→ 深く観測するほど危険  
→ 観測結果そのものが偽装されうる  
→ **情報が増えるほど正解に近づくとは限らない**  
→ 罠・偽装システムとFPSを組み合わせる  
→ **TRACE**

## TRACE — 痕跡推理FPS

### コンセプト

> **見るほど、見られる。信じるほど、罠に近づく。**

敵そのものを直接見るのではなく、敵が残した痕跡を読み、位置を推測するFPS。

相手はほぼ透明。プレイヤーは足跡・足音・物の揺れ・ペンキ・泡・水などから存在を推測する。ただし、痕跡は相手が意図的に作った偽装かもしれない。

### コアループ

**痕跡を見る**  
→ **本物か疑う**  
→ **追加観測する**  
→ **詳しい情報を得る**  
→ **観測したことで自分も露出する**  
→ **本物か罠か判断する**  
→ **撃つ / 撤退する / 逆に騙す**

重要なのは射撃そのものより、情報を読む・疑う・確かめる・騙すという意思決定。

### 中心となる構造

1. **見えない相手を痕跡から探す**
2. **情報を取りに行くほど、自分の情報も漏れる**
3. **観測 ↔ 被観測**
4. **情報の深さ ↑ = 露出リスク ↑**
5. **痕跡 = 手掛かりとは限らず、偽装かもしれない**
6. **情報が増えるほど正解に近づくとは限らない**

### 罠・偽装システム

TRACEの中心的な既存ゲームシステムとの組み合わせ。

**痕跡を見る**  
→ **本物か疑う**  
→ **追加観測する**  
→ **自分が露出する**  
→ **実は罠だった**

罠は単にダメージを与える装置ではなく、

> **相手に「もっと調べたい」と思わせる装置**

として設計する。

偽足跡、偽音、偽射撃痕、観測を誘う痕跡などによって、相手の判断そのものを操作する。

### キャラクター / モチーフ

軍事的な兵士ではなく、ゲームセンターの大型遊具・キッズライドから抽出した構造を使う。

- 大きく丸い塊
- 大きな顔
- 太く短いパーツ
- 乗り物と生き物が一体化したような形
- 原色・ツヤのある玩具的な質感
- かわいい動物モチーフ

候補として、ネコ・キツネ・アライグマ・タコ・モグラ等。それぞれ「足跡」「偽装」「擬態」「痕跡」「地中移動」などTRACEの構造と意味的につながる動物を使う。

かわいさはゲーム構造を幼児向けに変えるためではなく、**TRACEの緊張する情報戦を、かわいいモチーフで行うための構造交換**として扱う。

### 武器 / 道具

実銃ではなく、次の4系統を中心にする。

- **ペンキ**：透明な相手に付着し、当たった部分を可視化する
- **泡**：身体に付着し、輪郭や移動を一時的に見せる
- **水**：濡れた跡・足跡など追加の痕跡を発生させる
- **スタンプ**：相手や地面に印を残す。真の痕跡にも偽装にも利用できる

基本思想：

> **撃つ = HPを減らすだけではなく、情報を発生させる。**

射撃そのものも銃声・飛沫・痕跡などを生み、自分の存在を他者へ漏らす。

### 最小JS実験

最初から完成したオンラインFPSを作らない。

初期実験候補：

- HTML + JavaScript / Three.js
- 1マップ
- 1人 vs AI
- 相手はほぼ透明
- 足跡
- 集中観測
- 偽足跡または偽装痕跡
- ペンキ武器を1種類
- 射撃で相手の一部が可視化

観測したいのは、

- 足跡を追いたくなるか
- 「これは偽物かもしれない」と疑うか
- もっと情報が欲しくなるか
- 追加観測による露出を怖いと感じるか
- 相手を騙したくなるか
- 射撃より偽装の方が面白い等、想定外の行動が生まれるか

ここで得られた現象を、再び岡田エンジンへ投入する。

## 今回の位置づけ

TRACEはPRINCIPLE LOOPの完成形ではなく、**一つの構造が観察から抽出・再帰・変形・既存システムとの組み合わせ・モチーフ交換を経て具体化された「1案目」**として保存する。

作品を作るたびに新しい現象を発見し、それを次の構造へ変換することがPRINCIPLE LOOPの目的。
