# YOKOI SHIFT（横井シフト） v1.2

更新日：2026-10-09

## 位置づけ
PRINCIPLE LOOP の独立した選択式思考モジュール。名称は **YOKOI SHIFT（横井シフト）** とし、「横井軍平エンジン」「YOKOI ENGINE」は使用しない。常時実行・固定パイプライン化しない。

## 中心原理
**前提を維持し、用途や関係を転換する。**

横井軍平の「枯れた技術の水平思考」などの制作思想を研究上の手掛かりとする。ただし以下は PRINCIPLE LOOP 独自の運用仮説であり、本人が明示した手順と混同しない。

## 入力と不変条件
- 人間が「絶対に守る前提（CORE LOCK）」を自然文で指定する。
- 指定された前提を削除・置換・弱体化しない。前提に含まれないジャンル、目的、操作、世界観は固定しない。
- 例：**「画面の中に生き物がいる」** は必ず守る。育成・会話・捕獲などは前提に含まれない限り必須にしない。

## 選択式の発想操作
1. **用途シフト**：何のために存在するかを変える。
2. **操作シフト**：触る／触らない、動かす／観察するなどを変える。
3. **関係シフト**：生き物と人、複数人、第三者の関係を変える。
4. **時間シフト**：待つ、留守にする、過去と未来などを変える。
5. **目的シフト**：勝敗・育成・収集という既定の目的を外す。
6. **制約活用**：画面の境界、端末の向き、見えない時間などを遊びの資源にする。

## 実行プロトコル
1. 前提を一文で復唱し、守る条件と自由に変えられる条件を分ける。
2. 上記のシフトを任意に選択・組み合わせ、異なる方向へ案を展開する。
3. 各案に「変えなかった核」「変えた関係・用途」「プレイヤーに起こること」を記す。
4. 前提違反のみを検出・修正する。面白さや市場性による選別はこの段階で強制しない。
5. 必要に応じて林フィルター等の別モジュールへ渡す。順序も接続も任意。

## 例（仮説的な試案）
固定前提：画面の中に生き物がいる。
- iPad を裏返している間に、生き物が何かをしている（時間・制約シフト）。
- 生き物の視線から、画面の外の出来事を推理する（関係・用途シフト）。
- 生き物を直接操作せず、周囲の環境だけを変える（操作シフト）。

## 研究・更新の原則
横井軍平本人の一次資料／制作事例からの推論／PRINCIPLE LOOP独自拡張を区別する。成功例の固定テンプレート化は避け、未知の方向を探索し続ける。既存の他モジュールを上書きしない。


## v1.1 追加研究：製品別の「固定／捨てる／転換」比較（2026-10-09）

以下の「固定」「捨てる」は製品の特徴からの**分析仮説**であり、横井本人がそのように明言したことを意味しない。横井本人の発言・第三者証言・後年の分析を分けて検証する。

| 製品 | 維持した価値・機能（仮説） | 捨てた／疑った条件（仮説） | 新たな体験・実現方法 | 留保 |
| --- | --- | --- | --- | --- |
| ウルトラハンド（1966） | 遠くの物をつかむ | 手を直接届かせる | 伸縮機構で手の動きを拡張 | 本人の意図の確認は別途必要 |
| ラブテスター（1969） | 人と人の関係を遊びにする | 科学的に正確な恋愛測定という期待 | 数値をきっかけに会話を生む | 「捨てた」意図は未確認 |
| ゲーム＆ウオッチ（1980） | 手元でゲームを楽しむ | 大きな画面が必要という前提 | 小さな専用画面で遊ぶ | 本人の画面サイズに関する説明がある |
| 十字キー（ゲーム＆ウオッチ／ファミコン） | 方向を入力する | 従来型ジョイスティックの機構 | 薄い十字スイッチで方向入力 | 機構転換の経緯を一次資料で追加検証 |
| ゲームボーイ（1989） | 持ち歩いてゲームを遊ぶ | カラー化・高性能化を必須とする競争 | 携帯性・持続性を重視 | 本人は不要な機能の削除について説明 |
| バーチャルボーイ（1995） | 立体映像による新体験 | 通常の平面表示 | 覗き込む立体視ゲーム | 初期の用途未確定な実験と、製品化後の結果を区別 |
| ワンダースワン（1999） | 携帯ゲームの楽しさ | 画面の向きは固定という慣習 | 縦横の持ち方に対応 | 横井の死後発売。最終仕様を本人の決定と断定しない |

### 追加する選択式の発想操作（7〜9）

7. **固定観念の反証**：必要と思われる条件を特定し、他分野の観察や最小実験で本当に必要か検証する。
8. **機能と実現方法の分離**：達成したい価値・機能は残し、装置・形状・入力方法などの実現方法を置き換える。
9. **用途未確定の実験**：目的を早期に決めず、興味深い技術・現象を試し、そこから用途や遊びを発見する。

### 2つの任意モード

- **CORE LOCKモード**：人間が守る前提を指定する。前提は破らず、周辺の条件・実現方法・用途を変える。
- **OPEN EXPLORATIONモード**：用途未確定の技術や現象から始める。人間が明示的にCORE LOCKを指定していない場合に限り、固定前提を無理に作らない。

両モードは選択式。固定の実行順序、全操作の必須実行、他モジュールとの強制接続は設けない。成功事例への過剰適合を避ける。

### 根拠の区分と今後の検証

- **本人発言の研究入口**：横井軍平「私はなぜ任天堂を辞めたか」（『文藝春秋』1996年11月号、後年再公開）。「枯れた技術の水平思考」、画面サイズの固定観念、不要機能の削除、新しい商品領域についての本人の説明を確認する。
- **第三者証言**：宮本茂による横井軍平との開発経験の回想。本人発言とは別管理。
- **PRINCIPLE LOOP独自抽象化**：「固定観念の反証」「機能と実現方法の分離」「用途未確定の実験」、およびCORE LOCKとの接続は研究用の操作名であり、横井本人が提唱した名称ではない。
- **未検証**：各製品で何を意図的に捨てたか、失敗事例、本人の設計決定と開発チームの判断の境界。資料を追加し反証する。

## v1.2 過去記事・証言からの原理と構造（2026-10-09）

### 資料の読み方
- **A 本人の説明**：本人手記・本人インタビューの記述。発言の文脈を優先する。
- **B 事例からの推論**：製品の機能や開発経緯を比較した分析。本人の意図と断定しない。
- **C 第三者の証言**：宮本茂など共同制作者の回想。本人発言と区別する。
- **D PRINCIPLE LOOPの独自操作**：原理を再利用するための抽象化。横井本人の用語ではない。

### 研究上の7原理（本人の明示的な七箇条ではない）

| 原理候補 | 典型的な構造 | 根拠区分 | 例・注意 |
| --- | --- | --- | --- |
| 既存技術の異用途転換 | 成熟技術 → 用途を移動 → 新体験 | A＋B | 「枯れた技術の水平思考」。技術が古ければ必ず成功するわけではない |
| 固定観念の反証 | 必須だという主張 → 異分野の反例 → 必要条件を再定義 | A＋D | ゲーム＆ウオッチの小画面を、雑誌の小さな写真から考える |
| 機能と実現方法の分離 | 守る機能 → 機構を分離 → 別の実装 | A＋B＋D | 方向入力を十字スイッチで実現し、他製品へ移植 |
| 不要機能の除去 | 達成したい体験 → 使用実態を検討 → 不要機能を削る | A＋D | ゲームボーイ等のハード・ソフトの一体検討 |
| 用途未確定の試作 | 興味深い現象・工作 → 試作 → 他者の反応 → 用途を発見 | A＋B＋D | ウルトラハンド／バーチャルボーイ初期構想。商品化の成功を保証しない |
| 競争領域の転換 | 既存市場での性能競争 → 別の価値軸 → 新しい商品領域 | A＋D | 世界にない商品を作るという本人の商品哲学 |
| 最小変更・最大体験差 | 体験を左右する一点を探す → 一点を変更 → 遊びが変わる | C＋D | 宮本茂の回想に基づく補助仮説。本人が定式化したものではない |

### 2種類の出発点（独自の整理）
**目的起点**：実現したい価値・機能を守る → 常識や余分な条件を疑う → 実現方法を変更する。例：ゲーム＆ウオッチ、十字キー。

**可能性起点**：面白い現象・技術を見つける → 先に試す → 用途や価値を発見する。例：ウルトラハンド、バーチャルボーイ初期。

いずれも**任意の探索モード**であり、順序を固定しない。CORE LOCK指定時は人間が明示した前提を守る。OPEN EXPLORATIONでは用途を先に固定しない。

### 追加で見えた補助構造
- **他者が価値を発見する**：個人的な工作・試作が、他者の着眼によって商品企画になる場合がある（ウルトラハンドの事例）。「作者だけが価値を決める」とは限らない。
- **未知の案を早期に排除しない**：従来の市場基準で判断する前に試作・観察の機会を残す。ただし意思決定の集中を無条件に推奨しない。
- **遊びの成長を可視化する**：宮本茂によるシューティングトレーナーの回想に関連する別系統のゲーム設計仮説。YOKOI SHIFTの必須操作にはしない。

### 反証・限界
- 成功した製品から逆算すると、結果論や生存者バイアスが生じる。バーチャルボーイ等の難しかった事例も継続調査する。
- 「捨てたもの」は実際には開発制約やチーム判断だった可能性がある。横井個人の意思決定と断定しない。
- 目的起点と可能性起点は排他的ではなく、一つの製品の中で往復し得る。
- 研究の成功パターンを固定テンプレート化しない。BEST/FAR/WILDや他モジュールの独立性を維持する。
