# YOKOI SHIFT（横井シフト） v1.1

更新日：2026-10-09

## 位置づけ
PRINCIPLE LOOP の独立した選択式思考モジュール。名称は **YOKOI SHIFT（横井シフト）** とし、「横井軍平エンジン」「YOKOI ENGINE」は使用しない。常時実行・固定パイプライン化しない。

## 中心原理
**前提を維持し、用途や関係を転換する。**

横井軍平の「枯れた技術の水平思考」などの制作思想を研究上の手掛かりとする。ただし以下は PRINCIPLE LOOP 独自の運用仮説であり、本人が明示した手順と混同しない。

## 入力と不変条件
- 人間が「絶対に守る前提（CORE LOCK）」を自然文で指定する。
- 指定された前提を削除・置換・弱体化しない。前提に含まれないジャンル、目的、操作、世界観は固定しない。
- 例：**「画面の中に生き物がいる」** は必ず守る。育成・会話・捕獲などは前提に含まれない限り必須にしない。

## 選択式の発想操作
1. **用途シフト**：何のために存在するかを変える。
2. **操作シフト**：触る／触らない、動かす／観察するなどを変える。
3. **関係シフト**：生き物と人、複数人、第三者の関係を変える。
4. **時間シフト**：待つ、留守にする、過去と未来などを変える。
5. **目的シフト**：勝敗・育成・収集という既定の目的を外す。
6. **制約活用**：画面の境界、端末の向き、見えない時間などを遊びの資源にする。

## 実行プロトコル
1. 前提を一文で復唱し、守る条件と自由に変えられる条件を分ける。
2. 上記のシフトを任意に選択・組み合わせ、異なる方向へ案を展開する。
3. 各案に「変えなかった核」「変えた関係・用途」「プレイヤーに起こること」を記す。
4. 前提違反のみを検出・修正する。面白さや市場性による選別はこの段階で強制しない。
5. 必要に応じて林フィルター等の別モジュールへ渡す。順序も接続も任意。

## 例（仮説的な試案）
固定前提：画面の中に生き物がいる。
- iPad を裏返している間に、生き物が何かをしている（時間・制約シフト）。
- 生き物の視線から、画面の外の出来事を推理する（関係・用途シフト）。
- 生き物を直接操作せず、周囲の環境だけを変える（操作シフト）。

## 研究・更新の原則
横井軍平本人の一次資料／制作事例からの推論／PRINCIPLE LOOP独自拡張を区別する。成功例の固定テンプレート化は避け、未知の方向を探索し続ける。既存の他モジュールを上書きしない。

### 追加する選択式の発想操作（7〜9）

7. **固定観念の反証**：必要と思われる条件を特定し、他分野の観察や最小実験で本当に必要か検証する。
8. **機能と実現方法の分離**：達成したい価値・機能は残し、装置・形状・入力方法などの実現方法を置き換える。
9. **用途未確定の実験**：目的を早期に決めず、興味深い技術・現象を試し、そこから用途や遊びを発見する。

### 2つの任意モード

- **CORE LOCKモード**：人間が守る前提を指定する。前提は破らず、周辺の条件・実現方法・用途を変える。
- **OPEN EXPLORATIONモード**：用途未確定の技術や現象から始める。人間が明示的にCORE LOCKを指定していない場合に限り、固定前提を無理に作らない。

両モードは選択式。固定の実行順序、全操作の必須実行、他モジュールとの強制接続は設けない。成功事例への過剰適合を避ける。

### 根拠の区分と今後の検証

- **本人発言の研究入口**：横井軍平「私はなぜ任天堂を辞めたか」（『文藝春秋』1996年11月号、後年再公開）。「枯れた技術の水平思考」、画面サイズの固定観念、不要機能の削除、新しい商品領域についての本人の説明を確認する。
- **第三者証言**：宮本茂による横井軍平との開発経験の回想。本人発言とは別管理。
- **PRINCIPLE LOOP独自抽象化**：「固定観念の反証」「機能と実現方法の分離」「用途未確定の実験」、およびCORE LOCKとの接続は研究用の操作名であり、横井本人が提唱した名称ではない。
- **未検証**：各製品で何を意図的に捨てたか、失敗事例、本人の設計決定と開発チームの判断の境界。資料を追加し反証する。
