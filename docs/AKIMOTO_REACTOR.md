# AKIMOTO REACTOR（秋元リアクター）

- Version: v0.2（研究仮説）
- Status: 独立した選択式モジュール／明示起動のみ
- Principle: Emergence（創発）
- Origin: 秋元康の企画・発言から着想を得た研究モデル。本人の思考の正確な再現を主張しない。

## 目的

**人間が面白さを発見し、参加・相互作用・フィードバックから、設計者が直接用意していない展開や新しい目的が生まれる条件を設計する。**

完成済みの面白い結果を増やすのではなく、参加者が面白い結果を生み出してしまう仕組みを設計する。

## 配置・起動

- PRINCIPLE LOOPの独立した選択式モジュール。常時実行しない。
- HAYASHI FILTER（林フィルター）で選ばれたアイデアの後に使える。ただし固定接続・固定順序・必須通過は設けない。
- 単独使用、またはOKADA ENGINE、MINAKATA COLLECTOR、HAYASHI FILTERなどと任意に組み合わせられる。
- ユーザーの判断を置き換えず、試作と観察を促す。

## 思考操作（v0.2）

1. **関係の観察**：誰が誰を応援・評価・利用・競争しているかを観察する。
2. **欲望と不満の検出**：「自分ならこうする」「ここに参加したい」という感情を探す。
3. **決定権の移動**：作者が決めていた部分を、人間・複数主体・偶然へ委ねる。
4. **異質なルールの移植**：既存の関係に見慣れない、しかし理解しやすいルールを接続する。
5. **結果の開放**：結果を固定せず、行動の相互作用による展開を許す。
6. **反応の循環**：現実の反応、不満、想定外の使い方を次の設計へ戻す。

### 設計するもの／委ねるもの

| 設計する | 参加者に委ねる |
| --- | --- |
| 明確な入口・最小限のルール | 選択・順序・工夫 |
| 行動への分かりやすい反応 | 発見・解釈・感情 |
| 安全・公正・負担の上限 | 新しい遊び方・目的の更新 |
| 相互作用とフィードバックの条件 | 予期しない物語・関係 |

**注意：** ランダムイベントを増やすだけでは創発とは呼べない。行動が別の主体に影響し、結果が次の行動を変える循環を重視する。

## 出力フォーマット

アイデア1件につき、原則3案を提案する。各案には以下を記す。

- 一文で分かる入口と最小ルール
- 誰から誰へ決定権を移すか
- 人間に委ねる選択・発見
- 主体間の相互作用とフィードバック
- 予想外に生まれ得る展開・新しい目的
- 失敗条件・負担・公平性・悪用リスク
- 最小実験と観察指標

## 検証指標

1. 自発的な再試行が起きたか
2. 予想→実験→検証が起きたか
3. 作者が教えていない新しい目的を参加者が作ったか
4. 他者への共有・協力・連鎖が起きたか
5. 参加者に過剰な負担や不公平が生じていないか

指標は実際の試遊・観察で確認する。熱狂やヒットを保証する数式は設定しない。

## 実験例：『くものす おえかき』

- **A せかいが つかう**：子どもが線を描き、動物が橋・寝床・罠など別用途に使う。
- **B おえかき リレー**：子どもの線に動物が描き足し、子どもがさらに応答する。
- **C くものす ゆうえんち**：描いた線が伸縮・反発し、動物の動きから遊具へ変わる。

まずAの簡単な入口から始め、子どもが自分で次の目的を発明するか観察する。Cの物理的な反応は、必要なら段階的に追加する。予想外の結果と、意味のないランダム挙動を区別する。

## 研究上の留保

- 秋元康のインタビュー、企画、成功例、不成功例の比較から更新する研究仮説である。
- 「創発」は秋元康固有の発明ではない。人物固有の判断と一般的な創発原理を区別する。
- 企画者が面白いと思うことと、実際に参加者が熱狂することは異なる。
- 成功例の後付け解釈を避け、不成功例・反例・副作用を記録する。
- 既存のPRINCIPLE LOOP AUTO、DAILY、DIARY、他モジュールの実行順序を自動変更しない。

## 起動用プロンプト

> AKIMOTO REACTOR v0.2で「［企画名］」を分析してください。決定権の移動、予想外のルール、反応の循環を使い、人間が自発的に面白さを生み出す仕組みを3案提案してください。各案について、最小ルール、委ねる部分、相互作用、予想外の展開、失敗条件、最小実験、観察指標を示してください。創発と単なるランダムイベントを区別し、本人の発言と研究仮説を混同しないでください。


## v0.3｜創発を異分野へ展開するための設計構造（2026-10-08）

v0.2の6操作は保持し、以下を研究用の拡張レイヤーとして追加する。**創発が起きる条件**と**人間が面白いと感じる条件**は別々に検証する。

### 5つの基本構造

| 構造 | 設計対象 | 確認する現象 |
| --- | --- | --- |
| 主体 | 人間・動物・AI・物体などの行動者 | 複数の行動があるか |
| ルール | 各主体ができることと制約 | 自発的な選択の余地 |
| 相互作用 | 行動が別の主体や環境に与える影響 | 協力・競争・連鎖 |
| フィードバック | 結果が次の行動へ戻る仕組み | 学習・適応・増幅 |
| 目的の変化 | 新しい使い方を許す余白 | 目的の自己生成 |

主体を置き換えただけでは同じ創発は保証されない。相互作用の構造も成立させる。

### 12の設計操作（仮説）

1. **決定権移譲**：作者から参加者へ決定権を移す。
2. **役割交換**：観客と演者などの役割を入れ替える。
3. **目的の開放**：参加者が目標を発明できる余地を作る。
4. **情報の非対称化**：主体間で知っている情報を変える。
5. **相互依存**：協力・交換しなければ達成できない関係を作る。
6. **競争導入**：限られた資源・順位などを競わせる（負担・公正性に注意）。
7. **偶然介入**：予測不能な要素を追加する（ランダムだけでは創発ではない）。
8. **痕跡の蓄積**：過去の行動が環境に残る。
9. **連鎖反応**：小さな行動が他主体へ波及する。
10. **ルール変化**：行動の意味や制約を途中で変える。
11. **集団形成**：参加者が自発的に関係・チームを作る。
12. **反応の再利用**：生じた結果を次の遊び・企画の条件にする。

全部を一度に使用しない。まず1〜3操作を選択し、最小実験で観察する。これらは秋元康本人が実際に用いたと確認された12手法ではなく、創発を扱うための研究仮説である。

### 創発の観察尺度（暫定）

| Level | 観察結果 | 解釈 |
| --- | --- | --- |
| 0 | 用意された演出が再生 | 通常演出 |
| 1 | ランダムに違う結果 | 変動 |
| 2 | 複数の行動が影響 | 相互作用 |
| 3 | 相互作用から新しい全体パターン | 創発候補 |
| 4 | 参加者が新しい目的やルールを発明 | 目的の自己生成 |
| 5 | 新しい遊びが他者に広がり変化 | 社会的創発 |

レベルは面白さの点数ではない。創発の判定には再現実験・反例・観察ログを使う。

### 異分野へ移植する構造例

- **アリの行列**：局所ルール × 痕跡 × フィードバック → 集団的な経路形成。
- **Minecraftの自由制作**：単純な操作 × 組み合わせ × 目的の自己生成 → 参加者独自の建築や遊び。
- **観客の応援**：模倣 × 同期 × 集団反応 → 個人を超えるパターン。

自然現象の創発と、人間が楽しむことを混同しない。

### v0.3で重点的に検証する3原理

- **目的の自己生成**：与えられた目標の先を参加者が発明する。
- **局所行動から全体現象へ**：単純な個別行動から複雑なパターンが生じる。
- **創発の再帰**：生じた現象が次の行動条件を変え、別の現象につながる。

### 実行時の出力

1. 入力アイデアの核を一文で示す。
2. 主体・ルール・相互作用・フィードバック・目的変化を分解する。
3. 12操作から1〜3個を選び、異なる方向性の案を3〜5件生成する。
4. 各案に、最小ルール／誰へ決定権を移すか／何を委ねるか／創発の機構／予想外の展開／失敗条件／最小実験／観察指標を示す。
5. 創発と単なるランダム・台本付き演出を区別する。
6. 子どもや参加者への過度な競争・依存・課金誘導・不公平を避ける。
7. 結果は仮説として残し、試遊・観察によって更新する。

- DAILY、DIARY、AUTO、既存エンジンの自動実行・既存仕様は変更しない。
