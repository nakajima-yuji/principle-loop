# AKIMOTO REACTOR（秋元リアクター）

- Version: v0.2（研究仮説）
- Status: 独立した選択式モジュール／明示起動のみ
- Principle: Emergence（創発）
- Origin: 秋元康の企画・発言から着想を得た研究モデル。本人の思考の正確な再現を主張しない。

## 目的

**人間が面白さを発見し、参加・相互作用・フィードバックから、設計者が直接用意していない展開や新しい目的が生まれる条件を設計する。**

完成済みの面白い結果を増やすのではなく、参加者が面白い結果を生み出してしまう仕組みを設計する。

## 配置・起動

- PRINCIPLE LOOPの独立した選択式モジュール。常時実行しない。
- HAYASHI FILTER（林フィルター）で選ばれたアイデアの後に使える。ただし固定接続・固定順序・必須通過は設けない。
- 単独使用、またはOKADA ENGINE、MINAKATA COLLECTOR、HAYASHI FILTERなどと任意に組み合わせられる。
- ユーザーの判断を置き換えず、試作と観察を促す。

## 思考操作（v0.2）

1. **関係の観察**：誰が誰を応援・評価・利用・競争しているかを観察する。
2. **欲望と不満の検出**：「自分ならこうする」「ここに参加したい」という感情を探す。
3. **決定権の移動**：作者が決めていた部分を、人間・複数主体・偶然へ委ねる。
4. **異質なルールの移植**：既存の関係に見慣れない、しかし理解しやすいルールを接続する。
5. **結果の開放**：結果を固定せず、行動の相互作用による展開を許す。
6. **反応の循環**：現実の反応、不満、想定外の使い方を次の設計へ戻す。

### 設計するもの／委ねるもの

| 設計する | 参加者に委ねる |
| --- | --- |
| 明確な入口・最小限のルール | 選択・順序・工夫 |
| 行動への分かりやすい反応 | 発見・解釈・感情 |
| 安全・公正・負担の上限 | 新しい遊び方・目的の更新 |
| 相互作用とフィードバックの条件 | 予期しない物語・関係 |

**注意：** ランダムイベントを増やすだけでは創発とは呼べない。行動が別の主体に影響し、結果が次の行動を変える循環を重視する。

## 出力フォーマット

アイデア1件につき、原則3案を提案する。各案には以下を記す。

- 一文で分かる入口と最小ルール
- 誰から誰へ決定権を移すか
- 人間に委ねる選択・発見
- 主体間の相互作用とフィードバック
- 予想外に生まれ得る展開・新しい目的
- 失敗条件・負担・公平性・悪用リスク
- 最小実験と観察指標

## 検証指標

1. 自発的な再試行が起きたか
2. 予想→実験→検証が起きたか
3. 作者が教えていない新しい目的を参加者が作ったか
4. 他者への共有・協力・連鎖が起きたか
5. 参加者に過剰な負担や不公平が生じていないか

指標は実際の試遊・観察で確認する。熱狂やヒットを保証する数式は設定しない。

## 実験例：『くものす おえかき』

- **A せかいが つかう**：子どもが線を描き、動物が橋・寝床・罠など別用途に使う。
- **B おえかき リレー**：子どもの線に動物が描き足し、子どもがさらに応答する。
- **C くものす ゆうえんち**：描いた線が伸縮・反発し、動物の動きから遊具へ変わる。

まずAの簡単な入口から始め、子どもが自分で次の目的を発明するか観察する。Cの物理的な反応は、必要なら段階的に追加する。予想外の結果と、意味のないランダム挙動を区別する。

## 研究上の留保

- 秋元康のインタビュー、企画、成功例、不成功例の比較から更新する研究仮説である。
- 「創発」は秋元康固有の発明ではない。人物固有の判断と一般的な創発原理を区別する。
- 企画者が面白いと思うことと、実際に参加者が熱狂することは異なる。
- 成功例の後付け解釈を避け、不成功例・反例・副作用を記録する。
- 既存のPRINCIPLE LOOP AUTO、DAILY、DIARY、他モジュールの実行順序を自動変更しない。

## 起動用プロンプト

> AKIMOTO REACTOR v0.2で「［企画名］」を分析してください。決定権の移動、予想外のルール、反応の循環を使い、人間が自発的に面白さを生み出す仕組みを3案提案してください。各案について、最小ルール、委ねる部分、相互作用、予想外の展開、失敗条件、最小実験、観察指標を示してください。創発と単なるランダムイベントを区別し、本人の発言と研究仮説を混同しないでください。
